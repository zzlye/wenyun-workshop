# 画布节点缩放排查记录

用户反馈拖动图片节点四角时出现 React #185，并要求移除图片右上角的“替换”按钮。

## 排查结论

- 截图中的 #185 表示更新嵌套层数超限。线上相同资源文件的报错位置落在弹层容器的 Effect 更新处，单凭该栈不能断定上游触发原因。
- 修改前的独立浏览器在双节点、十二节点、连接节点和连续四角拖动中未稳定复现该错误；本记录不将风险修复等同于已确定截图故障的唯一根因。
- 已验证原缩放路径每个鼠标移动事件都会写回全部节点并触发保存。窗口失焦后监听器仍可继续缩放，组件重渲染改变缩放依赖时也可能丢失监听器。
- 这段缩放路径已存在于 `fed19d6`（2026-06-03 初始提交），不是本次 NewAPI 更新新增；尚无证据能确定截图错误首次出现的提交。
- 另外复现了视频、音频空节点添加媒体后 Hook 数量变化造成的崩溃。这两处条件 Hook 由 `653e9df`（2026-07-04）引入，与截图 #185 属于不同错误。

## 修改行为

- 四角拖动按动画帧直接预览节点大小及相关连线，松手后才提交一次节点数据，保存和撤销记录随最终数据更新。
- 拖动时关闭跟随节点的工具栏；松手、窗口失焦或指针取消均结束本次缩放。没有移动时不写回节点。
- 保留锁定比例、自由比例、最小尺寸和原始媒体分辨率；拖动中外部重新渲染也保留预览。
- 移除图片上的“替换”浮动按钮，现有工具栏上传入口继续使用。
- 媒体空节点与有内容节点保持相同的 Hook 调用顺序。

## 验证结果

- 新增 11 项回归测试：原代码 5 项失败、6 项通过，修改后全部通过。
- 画布相关及视频设置测试：10 个文件、54 项全部通过。
- 浏览器生产构建验证：四个角的实时尺寸、连接线、松手保存、一次撤销全部通过；暗色与窄屏检查未出现页面错误。
- `npm run build` 的 TypeScript 检查与生产构建通过，版本保持 `0.4.13`。
- 全部测试共 580 项，526 项通过、54 项失败；在原提交的独立副本中重跑对应六个测试文件，同样为 54 项失败及 2 个未处理拒绝，未将其计为本次新增失败。
- 修改只提交到本地代码仓库，本次未构建 Docker 或更新线上服务。
