# 网站恢复记录

## 故障现象

2026 年 9 月 21 日，服务器续费重启后，`zzlye.xyz` 返回 502；同机 `api.zzlye.xyz` 仍可访问。

## 已确认原因

文运容器循环退出，日志为 `host not found in upstream "new-api"`。实际运行中的容器没有主机映射，但 `/opt/wenyun/compose.yaml` 已保存 `new-api: 172.19.0.1`。配置文件与运行容器不一致，导致重启后 Nginx 解析不到内部地址而退出。网关到 NewAPI 的连接、数据库和磁盘均正常。

## 本次恢复

先在隔离容器使用相同镜像和 Nginx 配置验证：缺少映射时启动检查失败；加入现有映射后检查通过；移除映射的回退副本再次出现原错误。

随后只重新创建文运服务，应用已经保存的配置：

```sh
docker compose -f /opt/wenyun/compose.yaml up -d --no-deps --force-recreate --pull never --no-build wenyun
```

文运版本保持 `0.4.13`，镜像 ID 保持不变。没有拉取镜像、构建 Docker、修改业务代码，也没有重启 NewAPI、数据库或 Redis。

## 验证结果

- 文运容器为 `running / healthy`，重启次数为 0。
- 主站、画布入口、西米露域名和 API 状态接口返回 200。
- 文运内部 `new-api:3000` 和文运 API 代理的状态请求成功。
- 原配置文件校验值没有变化，运行容器已经包含持久化主机映射。
- 回退仅在隔离副本验证，线上保留恢复后的服务。

原容器资料及配置备份保存在服务器 `/opt/wenyun/backups/recover-20260921-1129/`，目录只允许 root 访问。完整本地检查记录位于 `D:/tmp/website-502-20260921/VERIFICATION.txt`。

以后修改容器的环境变量、网络或主机映射后，需要重新创建相应服务，并核对实际容器配置；单纯重启旧容器不会应用这些变更。
