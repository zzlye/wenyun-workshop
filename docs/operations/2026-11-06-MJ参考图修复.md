# MJ 参考图修复

## 简介

修复 MJ 本地参考图被上游以 `invalid_reference_image` 拒绝的问题。Docker 版本保持 0.4.13，桌面升级至 0.4.23。

## 如何使用

网页版刷新后继续添加参考图生成。桌面安装 0.4.23 后使用相同方式，无需自己寻找图床。已失败任务需要确认后重新提交，系统不会自动重发。

## 功能介绍

- 本地参考图自动转换为临时公网图片地址，多张图片保持顺序。
- 已有公网参考图地址原样保留，普通文生图流程不受影响。
- 图片到期自动清理，历史任务恢复只查询原任务。

## 原因与实现

- 旧机任务记录 `60ae9716-99a3-4ea8-9ad5-6927c4140eb4` 对应上游任务 `async_TgxlQo1n4KgOBqmrvaEIy3horqXlAqec`，记录了 HTTP 400 与“只支持公网 HTTP(S) 图片链接，不支持内联 Base64 图片数据”。
- 原 MJ 请求将参考图 Data URL 原样放入 `image/images`；模拟同样校验的上游可稳定复现。
- 网页任务服务首次提交前转换参考图，覆盖生图工坊、画布及已打开的旧页面。桌面本机任务服务调用网站托管接口，避免提交本机地址。
- 托管配置：`IMAGE_REFERENCE_PUBLIC_BASE_URL=https://xn--v5z30ywuk.com`，保存于任务目录下独立的 `references` 子目录。只向固定上游 `/models` 验证令牌，不创建额外生成任务。
- 图片地址随机不可枚举，有效期 24 小时；只接受 PNG/JPEG/WebP/GIF，单张 20MiB，存储总量 1GiB、最多 10000 个文件；每个 Key 每小时最多上传 256MiB。
- 公开地址不包含 API Key，读取不需要登录；超期不能继续读取。托管端保留原文件字节，不修改图片内容。

## 验证

- 修复前测试复现 Base64 被拒绝；修复后通过 URL 原字节读取、参考图顺序、桌面上传、鉴权、容量、重启及过期清理测试。
- 服务端 39 项、桌面 40 项、MJ 与画布客户端 75 项测试通过。
